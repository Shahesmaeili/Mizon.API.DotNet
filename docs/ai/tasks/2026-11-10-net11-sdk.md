## Implementation

Production libraries and diagnostics now target `net11.0`. All three Microsoft
runtime-adjacent direct references use stable `11.0.0`: SignalR.Client,
Extensions.Caching.Memory and Extensions.Http. Their availability was verified
against the official NuGet flat-container indexes before changing the project.
`global.json` selects SDK 11.0.100, patch roll-forward, no prerelease fallback.

No DTO, endpoint, session, authorization, download, streaming or cache behavior was
changed. Public package IDs/version remain unchanged; this is source publication,
not a NuGet release. Existing source-generated JSON and AOT analysis remain enabled.
The old standalone Tizen workload installer's version map is a different vendor's
historical workload catalog; it is not a .NET project TFM and was not rewritten.

`Tools/SdkBenchmarks` adds four repeatable scenarios through production code:
cached GET, small JSON GET, large JSON with 1,200 rows, and incremental global
search with 200 mixed music/profile items. It validates content, request counts,
row checksums and preserves all nine samples per process. It never reaches a real
network service. Allocated bytes are not retained app RAM. See its README for
methodology and the cross-repository server report for measured comparisons.

## Checks actually run

All commands were run from the isolated SDK worktree, sequentially:

1. Original baseline: .NET SDK 10.0.400-preview.0.26322.102, runtime 10.0.9,
   Microsoft package versions 10.0.14. Published the same benchmark source before
   migration and verified fixtures with `SdkBenchmarks.exe --verify` — passed.
2. Baseline `dotnet run --project Tools/SdkDiagnostics/SdkDiagnostics.csproj -c Release`
   — passed transport/cache/errors/cancellation, operations, media and loopback
   SignalR lifecycle checks.
3. Candidate `dotnet publish Tools/SdkBenchmarks/SdkBenchmarks.csproj -c Release --no-self-contained`
   under SDK 11.0.100/runtime 11.0.0 — passed without warnings/errors.
4. Candidate fixture verification and the same managed SDK diagnostic suite — passed.
5. `dotnet publish Tools/SdkDiagnostics/SdkDiagnostics.csproj -c Release -r win-x64 -p:PublishAot=true`
   using a separate artifacts directory — passed without warnings/errors.
6. Published native diagnostic executable — passed, dynamic code and JSON reflection
   disabled. This validates exercised SDK paths, not every Mizon UI or EF path.

Archived benchmark executables and logs live outside Git in
`D:/MizonTaskDiagnostics/Net11/{baseline,candidate}/sdk` and `sdk-*.log`.
The integration owner runs timings in alternating process order after all builds
finish. The comparison includes runtime, compiler and package upgrades; it is not
isolated proof of CLR-only performance changes.
